지표계산답하는 질문
micro전 레포 항목을 합산해 계산 — 큰 레포가 무겁게 반영코드 아무거나 집으면 규칙 지켰을 확률 (강제 효과 측정용)
macro레포별 %의 단순 평균 — 레포 하나가 한 표평균적인 레포는 몇 점인가
median점수순 가운데 레포보통 레포는? — 이상치에 안 흔들림
범위꼴찌 ~ 1등 레포편차 (좁으면 전사 규칙, 넓으면 레포별 복불복)

읽는 법 — micro·macro가 벌어지면 신호: py 에러 87.0 > 81.3 = 작은 레포가 말아먹는 중(이상치 api-llm·llm-gateway가 소형이라 macro만 끌어내림). go 테스트 7.6 < 12.2 = 반대로 레포가 클수록 못 지킴(app-ctl 2,049 assert가 4.5%). py 네이밍 median 99.2 + 범위 93~100 = 절반 이상 만점급, 문제는 꼬리 몇 개뿐. 우선순위: 강제 효과는 micro로 추적, 수리는 범위 하단부터.

인사이트

  1. 네이밍은 사실상 해결된 축. 양 언어 micro 97%+. 꼬리는 국소적 — git-executor(91%, stutter 88), api-service(95.5%, PascalCase 파일 237). v3 약어 검사에서도 go는 위반 0, py는 37건뿐.
  2. py 에러는 bimodal. 본대 87~100% vs api-llm 16.7%·llm-gateway 18.2% — 접미사 없는 예외 패밀리(BackendTimeout류)가 정체. LLM 계열 공통 습관.
  3. 테스트 축이 진짜 격차. go micro 7.6%(사실상 전무), py micro 31%. py 범위 7~64%가 보여주듯 언어 한계가 아니라 관행 — payments의 assert x == DTO(...)가 도달 가능 상한.
